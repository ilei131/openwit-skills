# 逐章执行细则

本文件是 `SKILL.md` 核心循环的展开版。较长任务时按需查阅，不必每次全读。

## 一、每章六步（缺一不可，任意一步不过不得进入下一章）

1. **读门槛**：首次开工读 `00/01/02/03/04` 全文；之后按本节「写前门槛」表读。
   缺文件或没读完即停，报准确路径，不得先写正文再补读。
2. **生成提纲**：把本章拆成 3—6 个场景/小节，标明每节的**目标、冲突、结尾**，
   并确认本章的"结尾钩子"。
3. **写正文**：按 `02_写作规范.md` 成文，落到 `chapters/第NN章_标题.md`，
   首行一级标题 `# 第 N 章 标题`。
4. **检查重复**：跑 `scripts/check.py` 并与既往章节比对，发现重复**必须改写**后再继续。
5. **更新进度与连续性**：在 `05_进度跟踪.md` 填状态/字数/验收结果；
   在 `06_连续性档案.md` 补本章状态卡、更新实体台账、承诺/伏笔台账与滚动摘要。
6. **本章验收**：对照 `04_验收标准.md` 逐条核对，全部通过 → 标记"已完成"；
   不通过 → 回到第 3 步修改。

> 只有当前章"已完成"，才允许开始下一章。

### 写前门槛（硬性）

首次开工前先读 `00/01/02/03/04` 全文。之后每个任务、每个会话按下表重新读；
表中限定"相关节/相关条目"的，按限定读，其余整份读到结尾。缺文件或没读完就停。

| 时刻 | 必读 | 按需读 |
|---|---|---|
| 写一章 | `04` 全文；`01` 本章条目；`02` 的文体/视角/禁忌相关节；`06` 滚动摘要 + 最新章节状态卡 | `03` 本章术语；`06` 相关实体台账与承诺/伏笔台账 |
| 续写 / 日更 | `05` 当前状态；`06` 滚动摘要 + 状态卡 + 台账；上一章正文结尾 | 本章细纲、相关设定 |
| 改稿 / 去 AI 味 | 被改章原文；`04` 改稿附加验收；`06` 相关状态卡与台账 | `02` 声音规范、`03` 术语 |
| 全书审计 | `00/01/04`；`06` 承诺/伏笔台账 | `03` 术语表、`05` 进度表 |

## 二、单章五要素

1. **开场钩子**：异常、误会、问题或动作，先抓住读者。
2. **明确目标**：本章主角想得到、避免或查明什么。
3. **有效冲突**：来自人物性格、价值观或既定规则，不靠角色突然变笨。
4. **人物/内容变化**：结尾与开头相比要有一处可指认的变化。
5. **结尾推进**：以新线索、未答的问题、关系变化或下一步行动收束。

写正文时的硬约束：

- 字数：按 `book.json` 的 `word_range`，不足则扩场景与对话，超出则删解释性文字。
- 视角与文风：遵守规范；专有名词、称谓一律用 `03_术语表.md` 的写法。
- 忌：说教式总结、金句堆砌、复刻他人原文、为凑字数注水。

## 三、重复检查

长文最怕"跨章重复"：同一句话、同一个比喻、同一套桥段反复出现。

**脚本查重**

- `scripts/check.py`：按句末标点切句，过滤过短通用短语，统计**同一句在几章出现**。
- `scripts/audit.py`：去掉标点后取固定字长窗口，统计**同一片段跨多少章出现**。

**判定与处理**

- 完全重复的句子（长度 ≥ `duplicate_min_len`）→ **必须改写**，目标为 0。
- 高频重复片段（跨 ≥ `duplicate_min_chapters` 章）→ 区分两类：
  - *机械重复*（固定叙述套话、比喻）→ 逐处改写；
  - *有意呼应*（母题、伏笔回扣、角色口头禅）→ 保留，但同一措辞全文不超过 2—3 次。
- 每次改写后**重跑脚本**，确认无新增重复。

## 四、连续性管理

`06_连续性档案.md` 是"全书记忆"，由四部分组成，缺一不可：

1. **实体台账**：人物、物件、地点、组织。人物至少记录外在目标、内在恐惧/缺陷、
   伤病、随身物品、情绪基线、当前目标；物件记录在谁手上、是否损坏或丢失。
2. **分章状态卡**：时间、地点、在场人物、人物状态、**知情矩阵**（谁知道了什么、
   谁仍蒙在鼓里）、物品状态、埋下/回收的承诺与伏笔、章末未决冲突。
3. **承诺/伏笔台账**：编号、内容、埋设章、计划回收章、状态（未回收/已回收/已废弃）、
   最近推进章。未回收超过 **15 章**必须优先安排回收或明确废弃。
4. **滚动摘要**：最近 3 章每章 100–150 字；更早章节每章一句话，只留改变主线的事件。

读写顺序：

- 每章写完：先更新状态卡与实体台账，再更新承诺/伏笔台账，最后改滚动摘要。
- 续写前：先读滚动摘要，再读最新章节状态卡，最后查相关台账；不回读全文。
- 冲突时**以本档案为准**；确需改设定，写"改写说明"并回溯更新受影响的章节。

定期检查：同一元素在不同章节的写法是否一致；伏笔是否按计划回收；
角色是否说出了他不该知道的事（知情矩阵是否被打破）。

## 五、每章验收清单

- [ ] 字数在 `word_range` 区间内
- [ ] 五要素齐备
- [ ] 结尾钩子与目录/总纲一致
- [ ] 术语、称谓一致
- [ ] 无跨章重复（脚本结果为 0 或仅剩有意呼应）
- [ ] 状态卡字段齐备（含知情矩阵、物品状态、章末未决）
- [ ] 实体台账已更新（人物/物件/地点状态）
- [ ] 承诺/伏笔台账已更新；超 15 章未推进项已处理
- [ ] 滚动摘要已更新（最近 3 章详细，更早一句话）
- [ ] `ai_lint.py` 的 blocking 为 0，或已登记到 `ai_ignore`
- [ ] 与 `06_连续性档案.md` 无矛盾
- [ ] 编号、标题、文件名规范

全部满足 → 标记"已完成"并写回 `05_进度跟踪.md`。

## 六、全书完成后的统一审计

不要只看单章，跑一次整体审计（`scripts/audit.py`）：

1. **编号与标题**：章序号连续、文件名与标题、首行标题与 `01_目录.md` 全部一致。
2. **术语**：全书扫描，确认无别名乱用、无中途改名。
3. **重复**：重跑查重脚本，处理跨章重复的句子与高频片段。
4. **格式**：引号、标点、数字用法、章节分隔统一（如中文弯引号 `“”‘’`）。
5. **占位符**：搜索 `待写/TODO/待补/（略）` 等，确认无残留。
6. **伏笔回收**：对照 `06` 的承诺/伏笔台账，逐条确认已回收、已废弃或有意保留。
7. **时间线**：跨章核对季节、日期、人物状态是否连贯。

发现问题 → 就地修复 → 重跑脚本，直到干净。

## 七、长任务执行策略

- **不要每章都停下来问**：用户授权"一次性写完"时，中途问题**自行修复后继续**，
  只在最后统一汇报。
- **善用子代理并行/分段**：把"读资料 → 写本章 → 查重 → 登记"打包成固定指令
  （可直接采用 `assets/templates/07_写作任务说明.md`），交给子代理逐章执行；
  主控只维护进度与连续性档案，避免上下文被整本书撑爆。
- **上下文管理**：每章写完后**不要回读全文**，只依赖 `05/06` 的精简摘要推进。
- **容错自愈**：会话中断/超时/文件被回滚时，先列目录、跑一次 `audit.py`，
  定位缺哪些章、哪些文件异常，补齐后再继续。
- **每完成若干章做一次抽样复核**，避免错误累积到全书末尾才发现。

## 八、常见失误与对策

| 失误 | 对策 |
|------|------|
| 每章风格漂移、术语改名 | 把规则写进 `02/03`，写作前必读，写完用 `audit.py` 核术语 |
| 跨章重复句、重复比喻 | 每章写完立刻跑 `check.py` |
| 前后设定矛盾 | 维护并每章更新 `06_连续性档案.md`，写作前必读 |
| 状态卡/台账/摘要不更新 | 每章按「状态卡 → 实体台账 → 承诺/伏笔台账 → 滚动摘要」顺序更新 |
| 改稿不备份、改完不更新台账 | 按第十节改稿模式：先备份，剧情级改动同步 `06` |
| 为把 AI 味数字归零机械删词 | 先看 `blocking`；`advisory` 与孤立软性词按语境判断 |
| 字数忽高忽低 | 每章用 `check.py` 统计字数，按区间扩写/删减 |
| 结尾不接钩子 | 每章验收时单独核对"结尾钩子"一项 |
| 中途卡住就停工 | 按第七节容错自愈，修复后继续，不空等 |
| 成品中文乱码 | 导出后抽样渲染一页确认 |

## 九、导出 Word 与 PDF

统一检查通过后，把章节合成为成品（`scripts/build.py`）：

- **合并稿**：生成 `书名.md`（封面 → 目录 → 分卷 → 各章正文）。
- **Word（.docx）**：用 `python-docx`。设置正文字体（含中西文）、首行缩进、
  1.5 倍行距、标题层级；封面、目录、分卷分页。
- **PDF**：无 LibreOffice/Pandoc 时，用 `reportlab`，注册 CJK 内置字体
  `UnicodeCIDFont("STSong-Light")`，用 `SimpleDocTemplate` + `Paragraph` 排版，
  A4、留边距、分页。

导出后**抽样渲染一页**（如 `qlmanage -t` 或阅读器截图）确认中文不乱码、分页正常。

> 依赖：`pip install python-docx reportlab`。
> 注意：新版 reportlab 在旧 Python 上可能报 `md5(usedforsecurity=False)`，
> `build.py` 已在导入前给 `hashlib.md5` 打兼容补丁。

## 十、改稿与回炉模式

触发：改第 X 章、重写、回炉、去 AI 味、修改某段。

1. **确认授权范围**：只改表达 / 允许结构调整 / 允许改剧情。范围不明先问；
   未授权不得改事件、动机、结果或人物选择。
2. **备份原稿**：复制到项目根 `work/改前原稿/{YYYYMMDD}_{原文件名}.md`，改后回读对照。
3. **读相关记忆**：按「写前门槛」的改稿行读取；只读本章相关状态卡与台账，不整读全书。
4. **执行改动**：
   - 只改表达：事实、人物选择、因果、伏笔、揭露顺序一律不动；不新增事实、人物、数字、引文；
     不用新微动作、粗话、证据硬造"真人感"。
   - 结构调整：可删无功能段落、调整详略、恢复承接；仍不改事件与结果。
   - 剧情改动：单独列出改动点，同步 `06` 状态卡、实体台账、承诺/伏笔台账与滚动摘要；
     必要时回溯更新后续章节。
5. **复检**：重跑 `check.py` 与 `ai_lint.py`；`blocking` 清零或全部在 `ai_ignore` 登记；
   对照 `04` 的"改稿附加验收"逐条核对。
6. **回读**：对照备份通读整章，确认事实、因果、情绪承接、空间方向、悬念没有丢；
   若引入新的套式，回到第 4 步再改。
7. **汇报**：说明改了哪几处、为什么改、哪些没有动、仍需授权的剧情缺口；
   不把规则名、脚本字段当评价。
